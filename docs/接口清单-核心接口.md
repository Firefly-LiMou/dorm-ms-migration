# 高校公寓管理系统 接口清单（核心接口）v1.0

范围：必做三大模块（用户认证与权限、宿舍基础信息与入住管理、报修管理）全部接口。
依据：《高校公寓管理系统需求分析》V1.0、《数据库表结构设计》、《后端架构设计》。
本文档为前后端联调契约基线，与 Knife4j 自动生成文档同步维护；任何接口变更必须先更新本文档，再修改代码。

## 一、术语表

| 术语 | 定义 |
| ---- | ---- |
| Result | 统一响应结构 `{code, msg, data}`，所有接口 body 均为该结构 |
| PageVO | 分页响应结构 `{total, pages, list}`，作为 Result.data 返回 |
| Token | 登录凭证，由登录接口签发，有效期 1 天 |
| DO | 与数据库表一一对应的实体对象 |
| isOverdue | 报修超时标识：待处理且提交超过 24 小时为 true |
| 入住记录 | dorm_checkin 表记录，status=1 表示入住中，status=2 表示已退宿 |
| 初始密码 | 新建学生账号的默认密码 123456 |

## 二、通用约定

1. 所有接口必须遵守 RESTful 风格：新增 POST、修改 PUT、删除 DELETE、查询 GET。
2. 所有接口基础路径必须为 `/api`，由后端 `context-path` 统一配置。
3. 所有接口 body 必须返回统一 `Result` 结构；`code=200` 表示成功，其他为错误码。
4. 权限异常必须返回真实 HTTP 状态码：未登录或 Token 失效为 401，越权为 403，body 仍为 Result 结构。
5. 业务错误必须返回 HTTP 200，通过 body 中 code 区分错误类型。
6. 参数校验失败必须返回 code=400，msg 拼接字段错误提示。
7. 登录态必须通过请求头 `satoken: {token}` 传递，禁止使用 Cookie。
8. 分页入参必须为 `pageNum`（从 1 开始）与 `pageSize`（默认 10，最大 100）。
9. 所有时间字段必须为 `yyyy-MM-dd HH:mm:ss` 格式。
10. 所有接口响应时间必须 ≤ 1 秒。
11. 管理员写操作接口（新增、修改、删除）必须标注 `@OperationLog` 注解记录操作日志。
12. 学生角色接口必须仅返回本人数据，服务端强制过滤，禁止依赖前端拦截。

## 三、错误码表

| code | 含义 |
| ---- | ---- |
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录或 Token 失效 |
| 403 | 无权限 |
| 500 | 系统异常 |
| 1001 | 账号或密码错误 |
| 1002 | 账号已禁用 |
| 1003 | 学号已存在 |
| 1004 | 原密码错误 |
| 2001 | 楼栋编号已存在 |
| 2002 | 楼栋下存在房间，禁止删除 |
| 2003 | 房间编号已存在 |
| 2004 | 房间下存在床位，禁止删除 |
| 2005 | 房间楼层超过楼栋总楼层 |
| 3001 | 学生账号不存在 |
| 3002 | 学生已有有效入住记录 |
| 3003 | 床位不存在或已被占用 |
| 3004 | 房间已存在床位，禁止重复初始化 |
| 3005 | 床位已入住，禁止删除 |
| 4001 | 无有效入住记录，禁止提交报修 |
| 4002 | 报修状态非法流转 |
| 4003 | 报修单不存在或当前状态不允许该操作 |
| 4004 | 入住记录未退宿，禁止删除 |
| 5001 | 数据不存在 |

## 四、接口明细

### 4.1 认证模块

#### 4.1.1 登录

- 路径：`POST /api/auth/login`
- 角色：student、admin
- 入参：

| 字段 | 类型 | 必填 | 校验规则 |
| ---- | ---- | ---- | ---- |
| username | string | 是 | 1-32 位 |
| password | string | 是 | 6-20 位 |

- 出参 data：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| token | string | 登录凭证，有效期 1 天 |
| userInfo | object | 用户信息：userId、username、realName、role、gender、phone |

- 错误码：1001、1002

#### 4.1.2 登出

- 路径：`POST /api/auth/logout`
- 角色：student、admin
- 出参 data：null
- 说明：注销当前 Token，前端同时清空本地登录态。

#### 4.1.3 获取当前登录用户信息

- 路径：`GET /api/user/profile`
- 角色：student、admin
- 出参 data：userId、username、realName、role、gender、phone
- 错误码：401

#### 4.1.4 修改个人信息

- 路径：`PUT /api/user/profile`
- 角色：student、admin
- 入参：realName（必填，1-32 位）、gender（可空，男/女）、phone（可空，11 位数字）

#### 4.1.5 修改登录密码

- 路径：`PUT /api/user/password`
- 角色：student、admin
- 入参：oldPassword（必填）、newPassword（必填，6-20 位）
- 错误码：1004

### 4.2 用户管理模块（admin）

#### 4.2.1 分页查询学生账号

- 路径：`GET /api/user/page`
- 角色：admin
- 入参：pageNum、pageSize、username（学号模糊）、realName（姓名模糊）、status（1 正常/0 禁用）
- 出参 data：PageVO，列表元素含 userId、username、realName、gender、phone、role、status、createTime

#### 4.2.2 创建学生账号

- 路径：`POST /api/user`
- 角色：admin
- 入参：username（必填，学号，1-32 位）、realName（必填）、gender、phone
- 说明：密码不传，默认初始密码 123456，BCrypt 加密存储；status 默认 1。
- 错误码：1003

#### 4.2.3 编辑学生账号

- 路径：`PUT /api/user/{userId}`
- 角色：admin
- 入参：realName、gender、phone、status
- 错误码：5001

#### 4.2.4 重置学生密码

- 路径：`PUT /api/user/{userId}/password/reset`
- 角色：admin
- 说明：重置为初始密码 123456。
- 错误码：5001

### 4.3 楼栋管理模块（admin）

#### 4.3.1 分页查询楼栋

- 路径：`GET /api/building/page`
- 入参：pageNum、pageSize、buildingNo（模糊）、area（精确）
- 出参 data：PageVO，列表元素含 buildingId、buildingNo、buildingName、floorCount、area、createTime

#### 4.3.2 查询楼栋下拉列表

- 路径：`GET /api/building/all`
- 说明：供房间管理、入住分配等场景下拉选择，返回全部楼栋，不分页。
- 出参 data：buildingId、buildingNo、buildingName

#### 4.3.3 新增楼栋

- 路径：`POST /api/building`
- 入参：buildingNo（必填，唯一）、buildingName（必填）、floorCount（必填，1-50）、area（可空）
- 错误码：2001

#### 4.3.4 编辑楼栋

- 路径：`PUT /api/building/{buildingId}`
- 入参：buildingNo、buildingName、floorCount、area
- 错误码：2001、5001

#### 4.3.5 删除楼栋

- 路径：`DELETE /api/building/{buildingId}`
- 说明：楼栋下存在房间时禁止删除。
- 错误码：2002、5001

### 4.4 房间管理模块（admin）

#### 4.4.1 分页查询房间

- 路径：`GET /api/room/page`
- 入参：pageNum、pageSize、buildingId、roomNo（模糊）
- 出参 data：PageVO，列表元素含 roomId、buildingId、buildingName、roomNo、floor、bedCount、roomType

#### 4.4.2 查询房间下拉列表

- 路径：`GET /api/room/list`
- 入参：buildingId（必填）
- 说明：供床位管理、入住分配下拉选择，返回指定楼栋全部房间，不分页。
- 出参 data：roomId、roomNo、floor、bedCount

#### 4.4.3 新增房间

- 路径：`POST /api/room`
- 入参：buildingId（必填）、roomNo（必填，同一楼栋内唯一）、floor（必填，1-50）、bedCount（必填，默认 4，1-12）、roomType（可空）
- 错误码：2003、2005

#### 4.4.4 编辑房间

- 路径：`PUT /api/room/{roomId}`
- 入参：buildingId、roomNo、floor、bedCount、roomType
- 错误码：2003、2005、5001

#### 4.4.5 删除房间

- 路径：`DELETE /api/room/{roomId}`
- 说明：房间下存在床位时禁止删除。
- 错误码：2004、5001

### 4.5 床位管理模块（admin）

#### 4.5.1 分页查询床位

- 路径：`GET /api/bed/page`
- 入参：pageNum、pageSize、roomId、status（0 空闲/1 已入住）
- 出参 data：PageVO，列表元素含 bedId、roomId、buildingName、roomNo、bedNo、status

#### 4.5.2 批量初始化房间床位

- 路径：`POST /api/bed/batch`
- 入参：roomId（必填）、count（必填，1-12）
- 说明：按 count 生成床位编号 1..count，status 全部为 0；房间已存在床位时禁止初始化。
- 错误码：3004、5001

#### 4.5.3 手动更新床位状态

- 路径：`PUT /api/bed/{bedId}/status`
- 入参：status（必填，0 或 1）
- 说明：仅用于数据纠错；正常入住/退宿由系统自动更新，前端操作按钮隐藏。
- 错误码：5001

#### 4.5.4 删除床位

- 路径：`DELETE /api/bed/{bedId}`
- 角色：admin
- 说明：物理删除床位；仅空闲床位可删除，已入住床位禁止删除。
- 错误码：3005、5001

### 4.6 入住管理模块

#### 4.6.1 入住分配

- 路径：`POST /api/checkin`
- 角色：admin
- 入参：userId（必填）、bedId（必填）、remark（可空）
- 说明：服务端按事务执行「锁床位行 → 校验床位空闲 → 校验学生无有效入住 → 更新床位为已入住 → 插入入住记录」。
- 错误码：3001、3002、3003

#### 4.6.2 办理退宿

- 路径：`POST /api/checkin/{checkinId}/checkout`
- 角色：admin
- 入参：remark（可空）
- 说明：仅可退宿 status=1 的记录；事务更新记录状态为 2、回填退宿时间，释放床位为空闲。
- 错误码：4003

#### 4.6.3 分页查询入住记录（管理员全局查询）

- 路径：`GET /api/checkin/page`
- 角色：admin
- 入参：pageNum、pageSize、buildingId、username（学号精确）、status（1 入住中/2 已退宿）
- 出参 data：PageVO，列表元素含 checkinId、userId、username、realName、buildingName、roomNo、bedNo、checkinTime、checkoutTime、status、operatorName、remark

#### 4.6.4 查询我的住宿记录

- 路径：`GET /api/checkin/my`
- 角色：student
- 说明：返回本人全部入住记录（含当前与历史），按入住时间倒序；前端展示当前住宿（status=1）与历史记录。
- 出参 data：同 4.6.3 列表元素

#### 4.6.5 删除入住记录

- 路径：`DELETE /api/checkin/{checkinId}`
- 角色：admin
- 说明：物理删除入住记录；仅已退宿记录可删除，入住中记录禁止删除。
- 错误码：4004、5001

### 4.7 报修管理模块

#### 4.7.1 提交报修

- 路径：`POST /api/repair`
- 角色：student
- 入参：repairType（必填，0-3：0 水电故障/1 家具损坏/2 网络问题/3 其他）、content（必填，1-500 字）、contactPhone（必填，11 位数字）
- 说明：服务端自动关联学生当前入住房间 room_id；无有效入住记录时禁止提交。
- 错误码：4001

#### 4.7.2 分页查询报修单（管理员）

- 路径：`GET /api/repair/page`
- 角色：admin
- 入参：pageNum、pageSize、status（0/1/2）、buildingId、startTime、endTime
- 出参 data：PageVO，列表元素含 repairId、userId、username、realName、buildingName、roomNo、repairType、content、contactPhone、status、isOverdue、handleResult、handleTime、handlerName、createTime
- 说明：isOverdue 由服务端计算：status=0 且 createTime 距今超过 24 小时为 true。

#### 4.7.3 分页查询我的报修

- 路径：`GET /api/repair/my`
- 角色：student
- 入参：pageNum、pageSize、status（0/1/2）
- 出参 data：同 4.7.2

#### 4.7.4 处理报修

- 路径：`PUT /api/repair/{repairId}/handle`
- 角色：admin
- 入参：status（必填，1 或 2）、handleResult（status=2 时必填，1-500 字）
- 说明：status=1 仅允许当前「待处理」状态；status=2 仅允许当前「处理中」状态；完成时回填 handlerId 与 handleTime。
- 错误码：4002、4003

### 4.8 操作日志模块（admin）

#### 4.8.1 分页查询操作日志

- 路径：`GET /api/log/page`
- 角色：admin
- 入参：pageNum、pageSize、operatorName（模糊）、module（精确）、operationType（精确）、startTime、endTime
- 出参 data：PageVO，列表元素含 logId、operatorId、operatorName、module、operationType、content、ipAddress、createTime
