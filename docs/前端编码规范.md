# 高校公寓管理系统 前端编码规范

## 1. 代码风格规范

### 1.1 命名规范

- 组件文件/组件名：大驼峰命名，如 `LoginForm.vue`、`RepairList.vue`
- 工具/配置文件：小驼峰命名，如 `request.js`、`auth.js`
- 变量/函数：小驼峰命名，动词开头，如 `getRepairList`、`handleSubmit`
- 常量：全大写 + 下划线分隔，如 `DEFAULT_PAGE_SIZE`
- 自定义事件：kebab-case 命名，如 `@submit-form`、`@change-status`

### 1.2 分层与职责

- 统一使用 Vue3 组合式 API + `<script setup>` 语法，禁止选项式 API 混用
- 目录分层强制约定：
  - `views`：页面层，仅负责页面组装与业务逻辑聚合
  - `components`：公共组件层，存放可复用组件
  - `api`：接口层，统一封装所有接口请求
  - `store`：状态管理层，存放 Pinia 全局状态
  - `router`：路由层，管理路由配置与守卫
  - `utils`：工具层，存放通用工具函数
- 禁止在组件内直接编写接口请求，所有接口调用必须封装在 `api` 对应模块中
- 单一职责原则，单个组件代码不超过 500 行，复杂页面拆分为子组件

### 1.3 代码健壮性

- 对象属性访问、数组遍历前必须做空值校验，避免空指针异常
- 解构赋值必须提供默认值，复杂数据结构提前判空
- 索引访问、循环遍历必须做边界判断，防止越界

## 2. 组件开发规范

### 2.1 状态强制覆盖

所有业务组件、列表页面必须完整覆盖四种状态，缺失任意一项视为不合格：

- 加载中（loading）：接口请求过程中展示加载状态
- 空数据（empty）：无数据时展示空状态占位
- 错误（error）：请求失败时展示错误提示与重试入口
- 正常数据：请求成功时展示业务内容

### 2.2 Props 规范

- Props 必须显式定义类型、默认值，必填项标注 `required`
- 禁止透传过多 Props，复杂场景使用状态管理或插槽
- 二次封装 Element Plus 组件必须保留原生属性透传能力

## 3. 异常处理规范

### 3.1 异常分类

- 接口异常：网络错误、服务端错误码，由请求拦截器统一基础处理，业务层按需二次处理
- 业务异常：前端业务规则校验失败，如表单不通过、状态不合法
- 运行时异常：数据解析失败、渲染异常，兜底捕获并记录日志

### 3.2 处理原则

- **本地优先**：当前组件可处理的异常必须就地处理（用户提示、重试、降级展示），禁止向上抛出未处理的原生错误
- **明确提示**：用户可感知的异常必须通过消息/弹窗给出友好提示，禁止静默失败
- **数据保留**：表单提交、状态变更异常时，必须保留用户已输入内容
- **禁止吞错**：禁止空 catch 静默忽略异常，至少输出错误日志

### 3.3 强制约束

1. 禁止使用 `try { ... } catch (e) {}` 空捕获静默吞错
2. 禁止直接向终端用户展示错误堆栈、原生报错信息
3. 表单提交必须做前置校验，校验不通过禁止发起接口请求
4. 所有异步操作必须编写失败分支逻辑，不能仅处理成功场景

## 4. 日志规范

### 4.1 日志分级

- 调试日志：`console.log` / `console.warn`，仅用于本地开发，生产构建自动移除
- 错误日志：`console.error`，记录异常堆栈与上下文信息
- 业务日志：关键操作（登录、提交报修、办理入住）记录操作上下文，便于排查

### 4.2 强制约束

1. 生产环境禁止保留调试日志，通过构建配置统一清理
2. 禁止在日志中输出密码、身份证号等敏感信息
3. 异常日志必须输出完整错误上下文，禁止仅打印简单字符串
4. 禁止在循环中高频输出冗余日志

## 5. 硬编码与常量治理

### 5.1 分类处理规则

| 类型          | 示例                         | 实现方式                                                |
| ------------- | ---------------------------- | ------------------------------------------------------- |
| 业务状态/类型 | 报修状态、用户角色、入住状态 | 模块内定义常量对象，禁止使用数字/字符串字面量           |
| 业务固定常量  | 默认分页大小、表单长度限制   | 就近定义模块级常量，通用常量存放至 `utils/constants.js` |
| 技术配置项    | 请求超时时间、Token 过期阈值 | 环境变量 + 配置文件，代码提供默认值                     |
| 环境依赖项    | 接口基础地址、静态资源路径   | `.env` 环境变量管理，代码中禁止硬编码明文地址           |

### 5.2 强制约束

1. 业务状态、类型必须定义为常量，禁止在业务逻辑中直接写 `0/1`、`"student"/"admin"` 等魔法值
2. 同一字面量在代码中出现 2 次及以上必须抽取为常量
3. 禁止创建跨多业务域的全局上帝常量文件，常量随所属模块就近定义
4. 环境配置统一使用 `import.meta.env` 读取，禁止散落硬编码地址

## 6. 接口请求规范

1. 统一使用封装后的 axios 实例发起请求，禁止直接使用原生 axios 或 fetch
2. 请求拦截器统一添加 Token、请求标识；响应拦截器统一解析后端 `Result` 结构、处理全局错误码
3. 所有接口必须设置超时时间，超时后给出明确用户提示
4. 列表类接口统一分页参数命名，与后端字段完全对齐
5. 接口参数必须做合法性校验，非法参数禁止发往服务端

## 7. 路由与权限规范

1. 全局路由守卫统一实现登录态校验，未登录用户自动跳转登录页
2. 基于用户角色动态渲染侧边栏菜单，无权限菜单不展示
3. 越权访问路由时统一跳转 403 兜底页面
4. 路由参数必须做合法性校验，异常参数跳转首页或兜底页

## 8. 代码审查验收标准

出现以下任意一项视为代码不合格：

1. 业务组件缺失 loading、empty、error 任意一种状态处理
2. 存在空 catch 静默吞错、异常无任何提示与处理
3. 业务逻辑中出现未定义为常量的魔法值（数字、字符串字面量重复出现）
4. 直接向用户展示原生错误堆栈、接口原始报错
5. 组件内直接编写接口请求，未统一封装到 api 层
6. 表单无前置校验、异步操作无失败分支处理
7. 生产代码残留调试日志、临时硬编码测试数据
